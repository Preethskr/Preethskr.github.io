Industry project · Automotive manufacturing

Multi-Model Vision Inference for Robotic Pick-and-Place

Working with the robotics team, I built the vision system that lets robot arms pick parts out of their original boxes and place them into kit boxes for workers further down the assembly line. Each part gets its own instance segmentation model, served dynamically through TorchServe, with automated training pipelines and AWS hosting integrated with edge devices.

  • Few-shot synthetic training data: realistic, cluttered training scenes are generated from a handful of template images per part. Orientation-aware augmentation handles parts that are usually stacked in the same direction.
  • Foundation-model masks: Segment Anything (SAM) produces the part masks that feed the data pipeline.
  • Multi-GPU serving: models are registered and scaled on a GPU inference server, and new workers are placed on whichever GPU has enough free memory.
  • MMDetection

Industry project · Internal tooling

Auto-Annotation for Industrial Parts

An annotation tool that combines foundation models (Meta's Segment Anything and vision-language models) with classical computer vision to label industrial parts automatically. When the automatic labels need fixing, annotators can switch to an interactive click-to-segment mode, so they only review and correct.

  • Locates the container using colour, then runs SAM to segment the parts inside it
  • Uses CAD data (expected part counts and dimensions) to filter out wrong masks
  • Interactive mode: click foreground and background points, then segment several images and save the masks
  • Supports SAM ViT-B, ViT-L and ViT-H, trading speed for accuracy
  • 12× faster inference (5s → 0.4s)
  • 50% less data preparation time
  • Segment Anything

  • OpenCV

Open source · Vision + language

Hazardous Scene Analysis for Remote Robot Operators

A two-stage pipeline that turns images of hazardous industrial scenes into structured JSON for a remote operator controlling a robot. Stage 1 runs open-vocabulary detection to find hazard-relevant objects. Stage 2 uses a small LLM to reason over the detections and their spatial relationships and return a hazard assessment with an explanation and a confidence score.

  • Swappable detectors: OWLv2 or Grounding DINO, both zero-shot from text prompts
  • Reasoning with Qwen2.5-1.5B-Instruct, small enough to run locally
  • Asks the operator a clarifying question when the combined confidence falls below a set threshold
  • Includes a ground-truth annotation tool and an evaluation script
  • Runs on Apple Silicon (MPS), NVIDIA GPUs (CUDA) or CPU
  • PyTorch
  • Hugging Face
  • OWLv2
  • Grounding DINO
  • Qwen2.5

Retrieval-augmented generation

RAG Pipeline with Hybrid Retrieval

A RAG pipeline that combines BM25 keyword search with semantic embeddings. It ingests multiple document formats and streams answers with source attribution. An abstraction layer switches between local on-device models (Ollama) and cloud LLMs. Response quality and faithfulness are measured with RAGAS.

Open source · Agentic system

Agentic Text-to-SQL for Business Analysts

A business analyst asks a question in plain English and gets back the answer, the SQL that produced it, and a plain-English interpretation. The agent uses Claude's tool-use API in a loop: it chooses a tool, the application runs it, and the model reads the result and decides the next step. The LLM never touches the database directly.

  • Dynamic schema discovery: five tools find schemas, tables, columns, foreign keys and categorical values as needed, instead of putting the whole schema in the prompt. This keeps it working on large databases.
  • Guardrails: read-only by default, with human approval before any write. Also an automatic row limit, a 10-second query timeout, and errors returned to the agent so it can correct itself and retry.
  • Pluggable layers: database adapters for PostgreSQL, Oracle, Tibero and SQL Server. LLM providers for Claude, Groq (Llama) and Gemini.
  • Memory: resumable sessions, with older turns summarised and stored as JSON or in Postgres. Logging is structured JSON.

Multi-Source RAG Q&A System

Industry project · Assembly-line optimisation

Task Allocation for Assembly-Line Workers

I extended and maintained an optimisation engine that assigns assembly-line work to workers while meeting production targets. It respects vehicle options, process and sequencing constraints, work environments, locations and tools. Clustering generates alternative assignment plans, and mixed-integer models solved with Gurobi optimise both single-worker and multi-worker processes.

Internal Carbon Pricing for Multi-Unit Firms

A game-theoretic internal carbon pricing mechanism, solving constrained optimisation problems to find optimal uniform and non-uniform tax structures across business units. It shows that non-uniform taxes preserve long-term competitiveness for hard-to-abate sectors, despite short-term profit trade-offs.
